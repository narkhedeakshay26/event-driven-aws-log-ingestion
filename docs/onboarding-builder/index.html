How a log file travels

New objects raise an event, the queue buffers it, and the consumer reads the object through a role scoped to exactly the listed buckets.

After it's live

    
    
      
  1. Add or remove a bucket
    The owner runs a stack Update with the new BucketNames. You edit the same bucket in sources.yaml. It's picked up within 30 s.
    2. 
      
  2. A bucket is missing on your side
    The consumer logs a warning and leaves the message. It retries and then waits in the dead-letter queue for 14 days. Nothing is dropped silently.
    3. 
      
  3. Redrive after a fix
    aws sqs start-message-move-task --source-arn <dlq-arn> moves failed messages back to the main queue.
    4. 
      
  4. Offboard
    The owner deletes the stack. That removes the queue, the role and the bucket notifications, and leaves other notifications alone.
