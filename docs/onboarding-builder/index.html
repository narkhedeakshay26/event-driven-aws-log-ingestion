S3 Log Onboarding Builder

Every customer deploys the same CloudFormation template and only picks Yes/No dropdowns. The stack finds their log buckets itself. Here you generate the one per-customer piece, a quick-create link carrying their External ID, plus your consumer config and the note to send. Nothing leaves this page.

Project: event-driven-aws-log-ingestionTemplate: cloudformation/onboarding-stack.yaml

How a log file travels

The bucket manager asks the account where its logs go, wires those buckets to one queue, and scopes the reader role to exactly them.

Onboard a customer

What you enter here is the same for every customer except the name and the External ID, which is generated fresh for each one.

After it's live

    
    
      
  1. The customer adds a log source
    With AutoRescan = Yes it's wired within a day. Otherwise they run the RescanNow output command or update the stack. Nothing changes on your side.
    2. 
      
  2. Logs in another account
    The stack names them in SkippedSources. The customer opens the same link in that account; add a second config entry with the same tenant.
    3. 
      
  3. A file can't be classified
    The consumer leaves it on the queue with a warning. It retries, then waits 14 days in the dead-letter queue. Set default_parser to catch it.
    4. 
      
  4. Offboard
    The customer deletes the stack. That removes the queue, the role and the notifications it added, and leaves their own notifications alone.
